# Local preview — implementation status

2026-10-31. App version `0.2.0`. This is a runnable English visual-only prototype, not completion of the evaluation/release gates in [v0.md](v0.md).

## Implemented

- Electron/React desktop workspace with source selection, local file playback, a draggable speaker-region selector, preview captions, transcript history, and text export.
- **You're Not on Mute** branding with a neutral white/graphite workspace, blue controls, restrained typography, and direct interface copy.
- Eight-path attention decoding with CTC/local GPT-2 candidate rescoring, measured on 60 development and 160 evaluation clips; see [accuracy report](accuracy-report.md).
- Graceful stop flushes the last usable interval before closing. Optional input diagnostics show real mouth crops and warn about a small source face.
- Real Auto-AVSR inference in a native Python process on this M1 Pro. No audio is sent to the recognizer and no remote inference service is used.
- Auto-AVSR is the only selectable model and produces sentence captions. VALLR's downloaded checkpoint currently produces phonemes only, and the compatible phoneme-to-text adapter weights are unavailable, so it remains out of the UI.
- MediaPipe close-/full-range face detection and the reference mouth alignment/crop/normalization pipeline. One clearly detected face is required in at least 80% of the interval.
- Source-frame callbacks and media timestamps, 25 fps timestamp resampling, approximately four-second completed intervals in the accuracy profile (provisional passes remain available with the fast profile), bounded pending inference, explicit gaps, and resets that reject stale results.
- Authenticated loopback communication, renderer sandbox/context isolation, narrow IPC, random per-launch credentials, one session at a time, and supervised Python service shutdown.
- Optional local speech sample and a settings shortcut when macOS denies capture permission.
- Optional speaker calibration: two short on-screen reading passages, one practice and one held out, compare three decoder choices and keep a profile only when held-out WER improves. Calibration never updates model weights.
- Pinned Python environment in `requirements.txt`; JavaScript lockfile, model provenance/checksum verification, install/run instructions in [readme.MD](../readme.MD).

For this version, selected video-region frames go to the **local** Python process for mouth extraction. A client-side landmark worker is not implemented yet. Captions appear inside the app; a separate always-on-top caption window remains future work.

## Verified on this machine

Hardware: Apple M1 Pro, 8 CPU cores / 14 GPU cores, 16 GB unified memory, macOS 15.6.1. Python 3.12.3, PyTorch 2.7.1.

- TypeScript checking and production Vite build pass.
- 25 Python tests pass, covering resampling, bounded buffers, timestamp errors/gaps, access control, unsupported languages, epoch resets, short-video flushing, image dimensions, and pooling equivalence.
- `pip check` reports no broken requirements; the virtual environment is isolated from global packages.
- The pinned checkpoint loads on MPS with strict parameter matching. Its spatial-only 3D pooling is replaced by an exactly equivalent framewise 2D operation, tested against the reference on CPU.
- The desktop smoke test uses the real model: it loads and plays the H.264 research fixture, receives completed text, verifies mouth-input diagnostics/help/minimum layout, and saves screenshots in `.cache/screenshots/`.
- The development-mode smoke test plays a 20-second fixture constructed by repeating the research clip and verifies at least four completed intervals. This tests scheduling/integration, not general speech accuracy.
- An early smoke run reported screen-recording permission **denied** and verified the permission guidance. The user later confirmed window capture works when iTerm is enabled in macOS Screen Recording settings. File playback works without screen-capture permission.

## Initial speed observations

Direct inference on the 2.2-second research clip produced text on this Mac. Warmed greedy-attention runs took approximately **0.35–0.38 seconds**, including preprocessing, with a real-time factor around **0.16–0.18**. A first uncached run took **7.43 seconds**; another process with cached kernels measured 0.87 seconds for its first decode. Model loading took roughly 2.7–3.4 seconds after initial library/cache setup.

These are individual short-fixture observations, not p95 latency, sustained capacity, or an accuracy benchmark. The reference transcript was not used or supplied to inference. Desktop frame acquisition/compression and interval boundaries can change predictions from those of direct file decoding. On one 2.2-second MPS sample, the four-path attention beam took about 1.5 seconds (RTF 0.69); the reference hybrid attention+CTC beam took about 14.4 seconds (RTF 6.56). The app now defaults to an eight-path attention beam with CTC and local-LM candidate rescoring (see [accuracy experiments](accuracy-report.md)); `--decoder hybrid` remains available for diagnostic comparison. A below-one real-time factor on a short clip does not prove the live stream will stay caught up.

## Next milestones

1. Grant macOS Screen Recording permission to Electron, restart the app, and validate browser/player window capture, cropping, source loss, and fullscreen behavior.
2. Build the representative, human-checked English evaluation set; measure WER/CER, false speech, coverage, and caption lag. Current captions can be inaccurate and are not calibrated confidence estimates.
3. Build a pose/blur/occlusion evaluation and compare landmark crops before changing the checkpoint-matched face alignment. The current alignment corrects scale, translation, and in-plane rotation but does not make a profile view equivalent to frontal speech.
4. Benchmark released pretrained VSR checkpoints (start with MultiVSR) against Auto-AVSR on the same held-out English clips before further custom training. Audit preprocessing, streaming lag, memory, and model terms. Do not train a new model on the one-minute enrollment passage.
5. Improve temporal boundary handling, nonspeech/scene-cut gating, and decoder quality. Current independent intervals can split words and combine speech across cuts. Evaluate a separate small language-model reranker on held-out speakers and text before enabling it.
6. Run the planned 30-minute simultaneous playback/capture/inference test with memory, queue age, dropped-frame, and thermal measurements.
7. Add a floating caption window and public distribution packaging once the local pipeline is useful and reliable.

Run `npm run dev` to open the app. **Try a sample clip → Start lip reading** is the quickest path to seeing real local recognition. Full setup is in [readme.MD](../readme.MD).
