# Accuracy experiments — 2026-10-31

The app now uses an eight-path Auto-AVSR attention beam, CTC candidate rescoring, and a small local GPT-2 language scorer. We selected weights on development clips and kept them fixed for evaluation. This is an improvement experiment, not evidence that arbitrary live speech is reliably transcribed.

## Current defaults

`config/decoder.json` selects beam 8, CTC weight 0.2, language weight 0.2, and token length bonus −0.2. Language scoring only ranks candidates generated by vision. It cannot freely rewrite the transcript. The original visual CTC silence threshold (0.02 activity) is preserved. The app does one completed decode per approximately four-second interval for this more expensive profile; expensive two-second provisional passes are disabled to avoid accumulating work.

All inference remains local and visual only. `scripts/setup_accuracy_assets.py lm` installs the local GPT-2 scorer. If it is absent, the app reports the missing assets and uses `config/fast-decoder.json`. Set `RML_DECODING_CONFIG=config/fast-decoder.json` to explicitly reproduce the original four-path decoder. The app's **Show what the model sees** checkbox displays sampled actual grayscale mouth crops from the current interval without writing captured video to disk.

## Dataset and measurements

We downloaded the first shard of [mattymchen/lrs3-test](https://huggingface.co/datasets/mattymchen/lrs3-test), revision `9c28ed4b7c87b720f030b5996ef6e7789d7f4a8a`. Its 661 entries contain 25 fps, 96×96 grayscale mouth arrays and dataset transcripts. These are already cropped: they do not evaluate our live face detector or screen capture. The shard supplies no speaker identity, so our deterministic 60 development / 60 evaluation partition is clip-disjoint, not demonstrated speaker-disjoint. References are dataset labels and have not been manually reverified. No evaluation transcripts enter inference, language-model scoring, or weight training.

WER uses lowercase word tokens with punctuation removed and apostrophes retained. Number spelling is not normalized: e.g. a digit string and spoken-out number words can count differently. Edits are counted within each utterance before aggregation. Empty predictions count as deletions. Do not compare these pilot numbers directly with paper benchmark scores.

| Pipeline | Development WER, 60 clips | Evaluation WER, 60 clips | Evaluation decode p95 | Evaluation real-time factor |
| --- | ---: | ---: | ---: | ---: |
| Original four-path attention | 34.98% | 30.92% | 1.83 s | 0.52 |
| Eight-path attention + CTC + local LM | 30.69% | 26.93% | 2.68 s | 0.76 |

On the 60 evaluation clips (401 reference words), errors fell from 124 to 108; insertions fell from 19 to 7. Both runs emitted text on every speech clip. The paired utterance-bootstrap 95% interval for the absolute WER reduction is 0.0–8.72 percentage points, so this small pilot does not establish a statistically clear general improvement. Speaker-level uncertainty cannot be estimated from this source. The additional confirmation and combined results follow.

The frozen configuration was then tested on 100 additional clips that were excluded from both the development and initial evaluation manifests. WER improved from **26.95% to 25.89%** on these clips. Across all **160 evaluation clips / 1,158 reference words**, WER improved from **28.32% to 26.25%** (328 → 304 errors, about 7.3% fewer errors). Insertions fell from **53 to 24**, while deletions rose from **46 to 65**. Thus fewer unsupported added words come with more omissions. Both pipelines emitted text on every speech clip. The combined paired bootstrap interval for the reduction was **0.086–4.33 percentage points**. The additional-100-clips interval alone included zero (−1.04–3.23 points). These are modest gains from a limited source, not reliable general transcription. Combined decode p95 increased from 1.92 s to 2.86 s, and RTF from 0.50 to 0.73.

Decode time excludes collecting the four-second window, screen capture, JPEG transport, and rendering. A 2.68-second decode is not a 2.68-second live caption delay. Real-time factor means processing seconds divided by video seconds; below one on short clips is not a sustained-streaming guarantee.

## Other experiments and decisions

- **Silence:** 20 frozen-mouth development controls produced zero false words with the new decoder. Frozen frames are synthetic controls and do not cover natural silent head/mouth motion. Retain real idle recordings as a required follow-up.
- **Capture compression:** JPEG quality 92 on 20 development mouth clips gave 24.29% WER. This is a recompression proxy, not an actual screen-capture accuracy measurement; the subset and preprocessing differ from the full 60-clip score.
- **Alignment audit:** the reference Auto-AVSR cropper already interpolates missing landmarks and smooths their geometry over a 12-frame window. The actual normalized input is an 88-pixel center crop with the reference grayscale conversion and mean/std. We preserved it rather than stacking another unvalidated smoothing filter over lip motion.
- **Streaming overlap:** implemented CTC forced word alignment, retention of real context frames, and temporal ownership of output words. On 30 short development clips, the approximate window simulation improved 27.23% to 25.45% WER. A stricter five-clip repeated-utterance boundary probe then worsened from 13.89% to 16.11% with 0.5-second overlap, with more insertions and higher compute. These repeated fixtures are integration controls, not natural evaluation speech. Overlap remains **off** by default; `RML_OVERLAP_SECONDS=0.5` or `1` enables research comparison. Its current merge is insufficiently robust for promotion.
- **AV-HuBERT:** downloaded the official visual-only `base_vox_433h.pt` from the [authors' model page](https://facebookresearch.github.io/av_hubert/), SHA-256 `84c83698c831b447cb75db0d14b72040c021c9a442ee1208d306b1091c00756d`. Converted it using the [Transformers port](https://github.com/nguyenvulebinh/AV-HuBERT-S2S), revision `841efba840404582b5c8e0073b9599cc367e9c5b`, with matching base dimensions, decoder heads, and unscaled embeddings. All checkpoint parameters are matched strictly; sinusoidal positional buffers are generated deterministically. No Fairseq installation or audio input is used. This port has not been numerically cross-checked against legacy Fairseq. It achieved **35.19% development WER**, RTF 0.24: faster, but no accuracy improvement on this development set. It stays outside the app's supported model list.
- **Combined visual models:** tested AV-HuBERT candidate proposals plus an Auto-AVSR greedy proposal, scored in a batch by Auto-AVSR attention/CTC and the local LM. Development-selected rescoring reached **31.76% WER**, worse than tuned Auto-AVSR's 30.69%, although faster (candidate-generation run RTF 0.54). It remains a research adapter.
- **MultiVSR:** inspected its official code and checkpoint URLs. Both model and visual-extractor downloads timed out; HTTPS without `www` and HTTP were also attempted. No MultiVSR checkpoint comparison was possible. Do not describe it as a failed recognition model; download access is the blocker.
- **VALLR:** the fixed 16-frame architecture actually returns **eight** CTC positions, limiting phoneme capacity when an entire long interval is compressed into that input. Added a prototype using consecutive native-rate 16-frame blocks and a pronunciation-constrained beam decoder backed by CMUdict. It returned no complete words on 12 GRID development clips (100% WER, counted as deletions). A three-clip crop/scaling audit compared full-face versus detected-face input and raw, unit, and symmetric pixel scales; mean phoneme error remained approximately **91–103%**. Some variants degenerated into repeated dictionary interjections. This tiny constrained-domain audit does not prove performance on all inputs, but it provides no basis for adding the decoder to the app or training an LLM to repair these outputs.
- **Uncertainty:** audited score-margin thresholds on development candidates. No threshold achieved both at least 80% utterance coverage and at most 20% WER on retained speech. A threshold of 0.3 retained only 20% of utterances; full-transcript WER rose to 87.12% when omitted words counted as deletions. Automatic margin-based abstention is therefore disabled. Margins are diagnostics, not calibrated confidence probabilities.
- **Compact training:** the earlier masked-video GRID pilot scored 77.2% held-out WER versus 69.1% for its supervised baseline; see [training notes](calibration-and-training.md). It did not justify replacing the pretrained recognizer. Broad self-supervised training or distillation needs a better validated teacher and substantially more suitable data.

## Reproduce the experiments

Python dependencies and all newly installed transitive packages are pinned in `requirements.txt`. Assets live in ignored `.cache/`; the setup scripts verify SHA-256 before use. Dataset/model terms remain those of their original publishers; keep research data and weights out of source control. Downloads require network access; subsequent inference is offline.

```sh
.venv/bin/python scripts/setup_accuracy_assets.py dataset
.venv/bin/python scripts/setup_accuracy_assets.py lm
.venv/bin/python scripts/prepare_accuracy.py --parquet .cache/datasets/lrs3-pilot.parquet --per-split 60
.venv/bin/python scripts/evaluate_accuracy.py .cache/accuracy/manifest.jsonl --split dev --options config/fast-decoder.json --device mps --output .cache/accuracy/dev-baseline.jsonl
.venv/bin/python scripts/evaluate_accuracy.py .cache/accuracy/manifest.jsonl --split dev --beam 8 --lm --device mps --output .cache/accuracy/dev-beam8-lm.jsonl
.venv/bin/python scripts/tune_decoder.py .cache/accuracy/dev-beam8-lm.jsonl --lm --output .cache/accuracy/beam8-tuned.json
.venv/bin/python scripts/evaluate_accuracy.py .cache/accuracy/manifest.jsonl --split eval --options config/fast-decoder.json --device mps --output .cache/accuracy/eval-baseline.jsonl
.venv/bin/python scripts/evaluate_accuracy.py .cache/accuracy/manifest.jsonl --split eval --options .cache/accuracy/beam8-tuned.json --device mps --output .cache/accuracy/eval-tuned.jsonl
.venv/bin/python scripts/compare_accuracy.py .cache/accuracy/eval-baseline.jsonl .cache/accuracy/eval-tuned.jsonl --output .cache/accuracy/paired-comparison.json
```

For AV-HuBERT, run `scripts/setup_avhubert.py` (downloads approximately 1.8 GiB of official checkpoint data and makes a local safetensors conversion), then pass `--model avhubert` to the evaluator. `--model ensemble` selects the proposal experiment. `--variant frozen` tests static input; `--variant jpeg` applies quality-92 JPEG. `--streaming --overlap 0.5` runs final-window simulation; it excludes provisional-pass compute. `scripts/audit_vallr.py` checks output shape and `scripts/audit_vallr_inputs.py` runs the small GRID input audit.

## Adaptation pilot and workflow

A rank-32 adapter trained for eight epochs on 120 GRID clips, selected on 16 speaker-3 clips, reduced CTC-only WER on 16 held-out speaker-4 clips (96 reference words) from **76.04% to 27.08%**. Validation WER fell from 51.04% to 18.75%. Test utterance filenames were excluded from the training/validation cache. This compares the CTC head before/after adaptation, not the app's attention/LM caption pipeline. Timing fields are omitted because evaluation uses cached encoder features. This small fixed-grammar result does not demonstrate conversational improvement, pose robustness, or safe silence behavior; the adapter is not installed into the app.

`scripts/train_ctc_adapter.py` freezes the visual encoder and original CTC head, caching features and training a small rank-32 residual adapter with CTC loss plus a teacher-distribution penalty. It selects the best epoch on validation data and evaluates a separate test split once. Its default GRID pilot uses speakers 1/2 for training, speaker 3 for validation, and speaker 4 for testing, with held-out utterance filenames excluded from training. Experimental weights stay in `.cache/accuracy/ctc-adapter/` and are never automatically loaded into the app.

For personal adaptation, provide a JSONL manifest with `video`, `reference`, `group` (recording session), `split` (`train`, `validation`, or `test`), and `label_status: "verified"`. Use different reading passages and recording sessions across splits. Correct the transcript to what was actually spoken. A displayed passage alone is not a verified transcript. Run:

```sh
.venv/bin/python scripts/train_ctc_adapter.py --manifest /path/to/recordings.jsonl --output .cache/accuracy/personal-adapter --device mps
```

The pipeline rejects overlapping sessions, repeated passages across splits, duplicate paths, and empty splits. Use a fresh output directory when changing inputs. It runs training on the MPS GPU; CTCLoss runs on CPU with gradients returned to MPS. The Neural Engine is not used. Even a successful GRID adaptation is evidence for that fixed grammar only; natural speech, silence, pose, and streaming regressions remain necessary before any adapter becomes an app default.

## Desktop and regression checks

The production build, 25 Python regression tests, and dependency checks pass. A real Electron smoke run verifies file playback, completed captions, actual mouth-input previews, help, and a 1000×740 minimum window without horizontal overflow. A separate owned window playing only the public fixture verifies macOS screen capture and two completed intervals. This looped-fixture check establishes capture/inference integration, not transcription accuracy or long-session stability. It saves no screenshots of the user's other windows. Screenshots are under `.cache/screenshots/`.

**Stop reading** now stops frame submission, flushes any usable tail of at least half a second, waits for pending inference, and closes after a completion acknowledgement. Source changes still cancel old work. The default overlap remains zero. A source-resolution hint warns when a detected face is small; this is a pixel-size heuristic rather than confidence calibration. Longer actual meetings, natural idle motion, and personal recordings remain unvalidated.
