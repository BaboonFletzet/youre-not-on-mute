# Speaker calibration and compact-model research

## One-minute speaker calibration

The app shows two original reading passages while the same on-camera speaker is captured. The first passage is the practice set; the second is held out. The recognizer evaluates its configured attention/CTC/LM candidate decoder, attention-greedy, and CTC-greedy decoders against the known text. It changes only the decoder profile, and only when the practice winner also improves held-out word error rate by at least two percentage points. Fewer than three intervals from either passage, or any inference backlog, rejects personalization and keeps the standard attention beam.

This is intentionally not neural-network fine-tuning. One minute is too little data to safely update a 250M-parameter visual model, and doing so could memorize the passages. The profile is held in memory for this app run and must be recalibrated for a different speaker. It does not train the visual encoder or claim speaker adaptation.

## Face detail and pose

The existing Auto-AVSR preprocessing already aligns the face using eye, nose, and mouth landmarks, which normalizes translation, scale, and in-plane rotation. The client now keeps up to 960×720 pixels and recommends a tight forehead-to-chin crop so the face receives more source pixels. This does not remove 3D yaw/profile distortion. The current checkpoint was not trained here with pose augmentation, and changing its crop geometry would create input mismatch. Next, collect pose/blur/occlusion measurements on held-out clips and compare candidate landmark aligners against the reference crop before changing the model input.

## Dataset and training path

- **GRID** is the practical first dataset: 34 talkers, 1,000 short sentences per person, video, word alignments, and transcriptions. Its fixed command grammar makes it useful for debugging alignment and training mechanics, but it is too narrow to validate free-form captions. The maintainers provide it for research use: [GRID corpus](https://spandh.dcs.shef.ac.uk/gridcorpus/).
- **LRS3** has substantially more natural, transcribed TED speech and varied speakers/conditions. Its access and research terms must be reviewed before downloading or using it beyond experiments: [VGG lip-reading datasets](https://www.robots.ox.ac.uk/~vgg/data/lip_reading/).
- **AV-HuBERT** is a reference self-supervised approach, but its training recipe requires large audiovisual corpora plus iterative frame-cluster labels. The official recipe describes LRS3/VoxCeleb2 preparation, clustering, and Fairseq training; that is not a reasonable from-scratch run on this 16 GB M1 Pro. [AV-HuBERT code and recipe](https://github.com/facebookresearch/av_hubert).
- **M1 Pro pilot:** downloaded the normal-quality GRID video/alignment archives for speakers 1–4 into ignored `.cache/datasets/grid/`. `scripts/train_compact_grid.py` pretrains a small 3D CNN by reconstructing masked mouth-region video, then fine-tunes a word-level CTC head on speakers 1–3 and evaluates on speaker 4. A 900-clip, one-epoch MPS run took about 72 s for masked-video pretraining and 42 s for CTC fine-tuning. Masked reconstruction loss fell from 0.0086 to 0.0049; held-out word error rate (WER) was **77.2%** on 100 clips. A one-epoch supervised-from-scratch run on the same amount of data scored **69.1% WER**. These are small, noisy pilot measurements on GRID's constrained grammar; the masked pretraining did not help in this run, and the checkpoint is not integrated into the app. Training ran on the MPS GPU; the Neural Engine was not used.
- Apple MLX also supports training and automatic differentiation on Apple Silicon's CPU/GPU, but would add a second model stack. Continue with PyTorch MPS until a larger run justifies comparing frameworks. [Apple MLX overview](https://developer.apple.com/videos/play/wwdc2025/315/).

Self-supervised video pretraining can use synchronized audio/video during research training without passing audio into the shipped visual-only inference path. It still needs a large, appropriately licensed corpus and a held-out speaker evaluation. Do not report GRID-only performance as general lip-reading accuracy.

## Language-model reranking

The app now uses an eight-path attention beam with CTC and local-LM candidate rescoring. The measured comparison, AV-HuBERT conversion/proposal experiments, VALLR phoneme audit, and rank-32 GRID adaptation pilot are described in [accuracy-report.md](accuracy-report.md). **MultiVSR** (2025) provides official multilingual checkpoints and a real-video inference pipeline; it is the first replacement candidate because it has runnable inference and later supports more than English. Its official runtime chunks video at 14 seconds, so streaming latency and adapting it to our face crops must be measured. The repository and checkpoint are in ignored `.cache/multivsr`; the official checkpoint host timed out from this machine during this review, so no model comparison has run yet. See the [official code and checkpoint instructions](https://github.com/Sindhu-Hegde/multivsr).

**VALLR** (ICCV 2025) is relevant to the proposed phoneme-token plus language-model design and is available for non-commercial research under CC BY-NC 4.0. The paper reports 18.7% WER on LRS3 ([paper](https://openaccess.thecvf.com/content/ICCV2025/papers/Thomas_VALLR_Visual_ASR_Language_Model_for_Lip_Reading_ICCV_2025_paper.pdf), [official repository](https://github.com/MarshallT-99/VALLR)). I retrieved the official 696 MB `VALLR.path` checkpoint through Google Drive's confirmed download endpoint; SHA-256: `967667d61e705b0bc78d40a3ec80dd7ec449aa1d4d90a5e83c0d4289309ef374`. It strict-loads as a 182.4M-parameter visual-to-phoneme model and ran on MPS. On one 2.2-second fixture, 16 sampled frames took about 1.0 s and produced two collapsed phonemes (`K Z`); this is a smoke check, not a WER result. The official repository contains an LLM-adapter training script, but no ready-to-use adapter weights. Because the downloaded visual checkpoint cannot produce words by itself, VALLR is not selectable in the app until sentence decoding is available and evaluated.

Benchmark candidates on the same representative clips with verified references: WER/CER, false-caption rate, face/pose coverage, per-interval latency, memory, and end-to-end stream lag. Keep GRID's masked-video pilot out of the production path: its held-out WER was worse than its supervised-from-scratch baseline. Do not pick a candidate from paper leaderboard scores alone, and do not let a fluent language model overwhelm visual evidence.

## Position tokens and silence

The current network already converts video frames into CTC subword tokens; CTC blank spans serve as its no-token state. A separate lip-position/viseme stream would need temporal training and a language decoder. Visemes are many-to-one with phonemes (for example, several consonants look alike), so a position classifier alone cannot reliably recover words. A `[SILENCE]` state can help a trained temporal model mark inactivity, but mouth motion also occurs outside speech. This is a research branch, not a zero-delay replacement: low-latency output requires a causal model and explicit streaming evaluation.
